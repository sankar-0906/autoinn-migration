# AutoInn: Prisma 1 to Prisma 7 Migration Guide

This document explains how to set up and use the modernized database layer in the AutoInn backend. The project has been migrated from Prisma 1 (Legacy) to Prisma 7 to support modern Node.js features and ensure high performance.

## 1. Prerequisites
- **Node.js**: v22 or higher
- **PostgreSQL**: v14 or higher
- **Prisma CLI**: v7.x

## 2. Environment Configuration
Create or update your `.env` file with the following:

```env
DATABASE_URL="postgresql://postgres:autoinn123@localhost:5432/autoinn_migrate?schema=default$default"
```
**Note**: The `schema=default$default` is critical as it contains all legacy production data.

## 3. The Setup Process
To initialize the Prisma environment on a new machine:

1. **Install Dependencies**:
   ```bash
   npm install @prisma/client @prisma/adapter-pg pg
   npm install --save-dev prisma
   ```
2. **Generate Prisma Client**:
   ```bash
   npx prisma generate
   ```

## 4. Connecting to the Database in Code
Prisma 7 requires an **explicit Driver Adapter** for direct PostgreSQL connections. You cannot simply use `new PrismaClient()` without configuration.

**Correct Initialization Pattern (ESM):**

```javascript
import { PrismaClient } from '@prisma/client';
import { PrismaPg } from '@prisma/adapter-pg';
import pg from 'pg';
import 'dotenv/config';

// 1. Create a PostgreSQL Pool
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });

// 2. Initialize the Adapter with the correct schema
const adapter = new PrismaPg(pool, { schema: 'default$default' });

// 3. Initialize Prisma Client with the adapter
export const prisma = new PrismaClient({ adapter });
```

## 5. Working with Scalar Lists (Arrays)
In the old system (Prisma 1), lists like `departmentType` were stored in separate "side-tables". In this Prisma 7 setup, they are now **Native PostgreSQL Arrays**.

- **Prisma 1 (Old)**: Required separate queries or complex joins.
- **Prisma 7 (New)**: `const dept = await prisma.department.findUnique({ where: { id } }); console.log(dept.departmentType);` (It's already a native JavaScript array!)

## 6. Schema Integrity
- **Side-Tables**: Legacy junction tables (like `_CustomerHasVehicle`) are still present and mapped as relations to ensure 100% data parity.
- **Constraints**: We have relaxed `NOT NULL` constraints where the legacy data had inconsistencies, ensuring your application doesn't crash on old records.

## 7. Troubleshooting
If you encounter "Relation not found" errors:
1. Ensure your `.env` has `schema=default$default`.
2. Check `prisma/prisma.config.js` to ensure it points to the correct schema file.
3. Re-run `npx prisma generate`.
